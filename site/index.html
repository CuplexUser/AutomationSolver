Make the rung remember

Program a Mitsubishi-style PLC on a grid editor, hit Run, and watch power flood the rung while a real machine moves in 3D beside it. Forty-five work orders take you from one contact driving one coil to a PID loop holding a tank on setpoint, and on to a stacker crane keeping two production lines fed out of one aisle of racking.

    The bench

    Three columns, all live at once

    The work order reads like a machine manual. The editor is a grid you fill with contacts, coils, timers and function blocks. The operator panel has real push buttons, e-stops, lamps and analog trends bound to X and Y addresses. Press Run and the rung lights up cell by cell as power floods it from the left rail.

    work order 02 · start / stop seal-in

    Keyboard first

    One letter places an instruction, arrows move the selection across rungs, and digit keys hold operator buttons, so the two-hand safety press can genuinely need both hands.

    Replay the failure

    Every failing scenario gets a button that re-runs it scan by scan with a scrubber. Jump to the first failing scan and watch the rung that did it.

    Trace strip

    A logic-analyzer view, one row per device, filled where the bit is high. Word registers draw as strip charts, because a regulator cannot be judged from one number.

    The machines

    The 3D view is an instrument, not a cutscene

    Nothing animates on its own. Every transform is a pure function of the state the process model computed from this scan's dt, so what you see is what the grader saw. Five scenes are hero models authored in Blender and loaded as glTF; two are drawn procedurally, because when the subject is a number moving, or a grid of stock, a shape that is that number reads better than geometry would.

    Second genre

    Or put the ladder away and wire a cabinet

    Six work orders drop ladder logic entirely. You wire the terminals of fixed components using IEC numbering, and the same document is editable from two views. Wires and terminals color by live net potential. Merge two supply potentials onto one net and the breaker trips, exactly as it would in the panel.

    Work orders

    Forty-five jobs, eleven categories

    Each category is its own ladder of difficulty, starting from something you can finish in a minute and ending in a capstone that combines everything in it.

    Basics3 jobsContacts, coils and seal-in logic.
    Timers & Counters4 jobsOn-delay, off-delay, oscillators and counting.
    Stations2 jobsA conveyor index and a two-hand safety press.
    Elevator4 jobsMulti-floor dispatch, up and down latches with a tie-break, and door interlocks.
    Control Cabinet6 jobsWire real 400 V starters terminal to terminal: DOL, two-station, reversing, indication.
    Packaging Machine4 jobsGroup boxes 2, 4 and 16 with pushers, a flipping lift and an out-feed.
    Pick & Place4 jobsIndex a robot arm between an infeed and a tray without overfilling it.
    Drill Station4 jobsClamp, spin up, drill and sort mixed stock through one automatic station.
    Process Control5 jobsScale a transmitter, build a P regulator by hand, then let a PID block kill the offset.
    Motion Control4 jobsSpeed references, drive ramp parameters and the stopping distance a load implies.
    Automated Warehouse5 jobsDrive a stacker crane by position sensor, search the stock table for the nearest slot, and keep two lines fed.

    Scoring is 85 marks for scenarios passed plus 15 for performance, and the performance marks only land once everything passes. Sequencing jobs spend them on cycle time against a declared par; regulating jobs spend them on integral of absolute error. So a correct but leisurely program is solved and unlocks what follows, and still has to be pipelined to reach 100.

    One engine, both sides

    The client and the server run the same simulation

    packages/client

    Grid ladder editor

    Contacts and coils drop onto a rung grid, just like a real MELSEC program. Series is AND, parallel branches are OR, and every scan the solver floods power from the left rail so you see exactly which cells are live.

    packages/shared

    Deterministic scan cycle

    A pure-TypeScript engine with zero runtime dependencies. It advances only by an explicit dt, never the wall clock, so the same program always produces the same trace. The lint config bans Date and Math.random here to keep it true.

    packages/server

    Authoritative grading

    Submit, and the server replays your program through the same engine against scripted scenarios, machine dynamics included. Client and server agree bit for bit, by construction.

    That is the architectural bet of the whole project: one simulation engine, shared by live play and grading. There is no second implementation to drift. The demo at the top of this page works the same way, in miniature: the solver animating the rung is the same code that graded it when you pressed Submit.

    Run it locally

    Clone, install, play

    git clone https://github.com/CuplexUser/AutomationSolver.git
    cd AutomationSolver
    npm install # no native modules, no C++ toolchain
    npm run dev # server on :4000, client on :5173

    Open http://localhost:5173, create an account, and start solving. The database is Node's built-in node:sqlite and password hashing is node:crypto scrypt, so npm install works on a fresh machine with nothing but Node. This page is the project's landing page: the full game needs the local server, which is what grades you.
